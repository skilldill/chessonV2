# Shakhmaty Game

Минимальный русский игровой клиент для существующего Chesson API. React, Vite,
`ChessBoard3D` из `react-chessboard-ui/3d`. Доска загружается отдельным чанком
только после открытия комнаты.

## Запуск

```sh
npm install
npm run dev -- --host 127.0.0.1 --port 5175
```

Нужен существующий API на `http://127.0.0.1:4000`. Vite проксирует `/api` и `/ws`.
Другой адрес задаётся переменной `API_PROXY_TARGET` (см. `.env.example`). Для
игры с ботом серверу нужен запущенный Stockfish; клиент не подменяет его
локальной имитацией. Регистрация для игры не требуется. Если API возвращает
авторизованный профиль, используется его имя и WebSocket-токен.

## Сценарии

- `/`: выбор игры с другом или ботом. Время, добавление, цвет и сложность
  выбираются в модальном окне.
- `/game/:roomId`: гостевое подключение, приглашение по ссылке, 3D-доска,
  сдача, предложение/принятие/отклонение ничьей, выход с подтверждением и
  результат партии. Третий посетитель подключается наблюдателем.
- `/create-room?mode=friend|bot&autoStart=1&timeMinutes=10&incrementSeconds=0`:
  автоматическое создание комнаты из лендинга. Поддерживаются `requestId`,
  `botDifficulty=super_easy|easy|medium|hard`, `color=white|black|random` и
  `gameMode=standard`. Повтор запроса использует тот же `requestId`.
- После перезагрузки прямой ссылки восстанавливаются позиция и сторона.
  На главной предлагается вернуться в сохранённую незавершённую комнату.
- Таймеры и результат остаются серверными; на игровом экране намеренно нет
  истории ходов, чата, профилей, подсказок и других панелей старого `client`.

## Структура

- `hooks/usePlayerIdentity`: гостевой профиль и необязательная авторизация.
- `hooks/useCreateRoom`: создание, ошибки, повтор и защита от двойного запроса.
- `hooks/useRoomConnection`: WebSocket, переподключение, состояние партии,
  таймеры, предложения ничьей, уведомления и очистка соединений.
- `hooks/useGameBoard`: локальные/внешние ходы, ориентация, восстановление FEN.
- `hooks/useGameActions`: подтверждения, ожидание ответа, блокировка ухода.
- `hooks/useGameDialogs`: приоритеты модальных состояний.
- `hooks/useClipboard`: копирование приглашения.
- `lib/game`: валидация ссылок, API-контракт, нормализация ходов через
  `chess.js`, окончания партий и русские сообщения.

## Проверки

```sh
npm test
npm run build
```

Тесты покрывают создание и повторы запросов, координаты чёрных, рокировку,
взятие на проходе, превращение, мат, восстановление доски, синхронизацию
собственных/чужих ходов, режим наблюдателя и очистку WebSocket.

Для ручной интеграционной проверки партии за чёрных с отдельным тестовым
соперником на локальном API:

```sh
node test/integration-peer.mjs ROOM_ID
```

Соперник играет `e4`, отклоняет первое предложение ничьей, предлагает свою
ничью и принимает следующее предложение. Работает только с локальным API
по умолчанию; другой тестовый сервер задаётся через `TEST_API_ORIGIN`.

## Production

### Яндекс Метрика

В production подключён общий с лендингом счётчик `113658367` с Вебвизором,
картой кликов и точным показателем отказов. В режиме разработки код не загружает
Метрику. Первый просмотр и переходы React Router отправляются через `hit`;
автоматический просмотр при инициализации отключён (`defer`), чтобы не было дублей.
В URL просмотров и реферерах исключаются query-параметры, в том числе `requestId`.
Новые события используют JavaScript API `reachGoal`:

| Идентификатор цели | Когда отправляется |
| --- | --- |
| `play_click` | Выбор друга или бота на главном экране игры или лендинга. |
| `room_created` | API успешно вернул идентификатор созданной комнаты. |
| `game_started` | Участник получил серверное состояние начавшейся партии с хотя бы одним ходом. |
| `game_completed` | Участник наблюдал активную партию и затем получил серверный результат. |

Режим передаётся в параметре `mode` (`friend` / `bot`), приложение — в `app`.
Для клика есть `placement` (`landing` / `game`), для создания — время и добавление,
для завершения — тип результата (`mat`, `pat`, `draw`, `resignation`).
События партии не отправляются для наблюдателей. Открытие уже завершённой комнаты
не считается новым завершением. Переподключения, повторные сообщения и перезагрузка
страницы не дублируют цели комнаты в пределах вкладки: используется `sessionStorage`
с резервной защитой в памяти. Это события участника, а не глобальный счётчик партий:
у двух игроков одной комнаты могут быть свои достижения цели. Обновления локальной
доски не отправляют события до подтверждённого состояния сервера.

В настройках счётчика необходимо добавить `https://3d.chesson.me` в дополнительные
адреса и создать четыре цели типа «Целевое событие» с идентификаторами из таблицы.
Эти действия в кабинете Метрики код приложения не выполняет. Склейка посетителя
между `шахматы-онлайн.рф` и `3d.chesson.me` отдельно не реализована; одинаковый счётчик
не гарантирует сквозную идентификацию на разных доменах.

Для DAU/MAU игроков используйте уникальных посетителей с целью `game_started`,
а не всех посетителей страниц. Это приближённая клиентская аналитика: блокировщики
могут не передать события, а возврат в незавершённую партию тоже засчитывается.

Игровой хост — `https://3d.chesson.me`. Лендинг остаётся на `шахматы-онлайн.рф`.
Приглашения формируются на текущем игровом хосте: `/game/<roomId>`.

```sh
npm run build
```

Публикуется `dist`. Нужен SPA fallback на `index.html` для `/game/*` и
`/create-room`, а также WebSocket-прокси `/ws/room` с Upgrade-заголовками.
По умолчанию production HTTP-префикс `/api/api`, как в существующем `client`.
Если новый nginx проксирует API напрямую без удаления `/api`, задайте
`VITE_API_URL=/api` при сборке. Для другого WebSocket-адреса задайте
`VITE_WS_URL`. Пример переменных находится в `.env.example`.

Dockerfile использует Node.js 24 для сборки и `serve` для SPA, как `client`.
Внутренний порт — 3003. В Compose сервис называется `shakhmaty-game`, контейнер —
`chesson-shakhmaty-game`. Локальные `node_modules`, `dist` и `.env` не копируются
в образ. Параметры `VITE_API_URL` и `VITE_WS_URL` задаются при сборке образа
через одноимённые build arguments; изменение runtime environment их не заменяет.

Корневой nginx.conf проксирует `/api/` с удалением первого префикса: запрос
`/api/api/rooms` приходит в API как `/api/rooms`. `/ws/room` передаётся без изменения
пути, с HTTP/1.1 и Upgrade-заголовками. На игровом хосте установлен `X-Robots-Tag: noindex`.
Внешний прокси завершает HTTPS и должен передавать `Host` и `X-Forwarded-Proto: https`.
Мобильные устройства используют тот же хост, без перенаправления на mobile.chesson.me.

Команды обновления Docker-стека приведены в `../shakhmaty/README.md`.
Существующие `client`, `mobile` и API остаются отдельными сервисами.
