# Переход со страницы игры с другом в созданную комнату

## Что уже готово в site

Обёртка страницы находится в `src/components/FriendGamePage.astro`, общая разметка
в `src/components/GameLandingPage.astro`, настройки в
`src/components/GameLandingSettings.astro`. Она открывается по существующему адресу
`/ru/play-chess-with-friends-link/` и по пяти дополнительным адресам:

- `/shahmaty_online_s_drugom_po_ssylke/`
- `/shahmaty_online_s_drugom/`
- `/onlayn_shahmaty_po_ssylke_s_drugom/`
- `/shahmaty_s_drugom_onlayn/`
- `/shahmaty_s_drugom/`

Все варианты используют canonical существующей русской страницы. В sitemap
остаётся основной адрес. Hero использует тот же `HeroBackdrop`, что главные
страницы на русском и английском.

Форма передаёт настройки на `/create-room` игрового домена. На мобильном устройстве
выбирается `mobile.chesson.me`, на компьютере `game.chesson.me`. При отключённом
JavaScript форма отправляется на `game.chesson.me`, а существующий Nginx-редирект
выбирает мобильный домен с сохранением пути и параметров.

Пример перехода:

```text
https://mobile.chesson.me/create-room?mode=friend&autoStart=1&gameMode=standard&source=friend-landing&timeMinutes=10&incrementSeconds=0&withAIhints=true
```

`withAIhints=true` передаётся только при включённых подсказках. Отсутствие параметра
означает `false`. Начальные настройки: 10 минут, 0 секунд добавления, подсказки
выключены. Доступные значения совпадают с полным набором desktop-приложения,
включая мобильные варианты. Настройки сохраняются на домене лендинга; localStorage
разных доменов не общий, поэтому приложения должны читать URL.

Автосоздание реализовано в client и mobile: специальный вход читает настройки,
вызывает существующий API и заменяет адрес на `/game/{roomId}`. Сам site не
отправляет запросы создания комнат. Обычный `/create-room` сохраняет каталог.

Форма добавляет UUID `requestId` при отправке; старые ссылки без UUID дополняются
приложением до запроса. API хранит результат попытки 10 минут в памяти, как и
сами комнаты. Повторный запрос возвращает ту же комнату, изменение настроек с тем
же UUID отклоняется. После перезапуска API эта защита не сохраняется.

Восстановление старой игры ограничено главными экранами. Перед открытием новой
комнаты сбрасывается сохранённая старая партия. Ошибки создания позволяют
повторить запрос с тем же UUID либо вернуться к ручным настройкам. Мобильный
экран ожидания теперь имеет отдельные кнопки копирования и системной отправки.

Из пунктов ниже остаются production-проверка после совместного развёртывания
site, client, mobile и API, а также настройка событий аналитики.

## Контракт и проверочный план

Автоматические проверки параметров и защиты повторных запросов: `cd api && bun test`.
Браузерная проверка: запустить site на 4321, client на 5173 и mobile на 5174
с `VITE_TEST_MODE=true`. Для изолированного API без MongoDB и Stockfish:

```sh
cd api
WITHOUT_MONGO=true PORT=4000 bun --preload=./test/friend-game-api.preload.ts ./index.ts
```

Этот тестовый сервер не предназначен для игры с ботом, подсказок или анализа.
Создание комнат и подключение игроков через WebSocket используют реальный код.
Затем в другом терминале из api выполнить `node test/friend-game-browser-check.mjs`.
Если браузер Playwright находится не в стандартном каталоге, передать абсолютный
путь к нему через `PLAYWRIGHT_CHROMIUM_EXECUTABLE`. Тесты не создают комнаты на
production: переходы на игровые домены перехватываются и направляются локально.

### 1. Выделить вход для создания партии

В `client/src/App.tsx` и `mobile/src/App.tsx` обработать специальный вход
`/create-room?mode=friend&autoStart=1`. Обычный `/create-room` сохраняет каталог.
Специальный вход показывает состояние создания партии и выполняет запрос сразу,
без повторного выбора режима и времени. Обязательная регистрация не нужна.

Реализовать одинаковый разбор параметров в обоих приложениях через
`URLSearchParams`. Разрешить только стандартную партию с другом (`vsBot: false`,
`gameMode: 'standard'`). Проверить минуты и добавление по спискам допустимых
значений из `site/src/data/friendGame.ts`; нечисловые значения, дроби, отрицательные
числа и отсутствующие обязательные параметры должны приводить к понятной ошибке
с переходом к обычным настройкам. Подсказки включать только при значении `true`.

### 2. Создать комнату существующим API

Использовать `useCreateRoom` каждого приложения. Endpoint на сервере уже существует:
`POST /api/rooms` в `api/index.ts`. Через production-прокси запросы идут с префиксом
из `constants/api.ts` (`/api/api/rooms`), его нельзя заменять вручную.

Для 10+0 запрос имеет такое тело:

```json
{
  "whiteTimer": 600,
  "blackTimer": 600,
  "increment": 0,
  "withAIhints": false,
  "vsBot": false,
  "gameMode": "standard"
}
```

Сервер возвращает `success` и `roomId`. В desktop-хуке дополнить проверку
`response.ok`; в обоих хуках требовать успешный ответ и непустой `roomId`.
Показать ошибку и кнопку повторной попытки при сбое, не оставлять бесконечную
загрузку. Создание обычной комнаты уже поддерживается API.

### 3. Обеспечить однократное создание

Отключить повторное действие во время запроса. Защитить вызов от повторного
эффекта React и повторного открытия страницы. Для надёжного поведения при
перезагрузке и потере ответа добавить идентификатор попытки: site генерирует
`requestId` при отправке формы, приложения передают его в API, сервер для той же
попытки возвращает ранее созданный `roomId`. Один только флаг в React не защищает
от повторного POST после перезагрузки. Срок хранения таких попыток ограничить.

### 4. Открыть созданную комнату

После успешного ответа заменить адрес на `/game/{roomId}`. На компьютере использовать
`history.replace`, на мобильном `window.location.replace` либо замену через router.
Это убирает страницу автосоздания из истории: кнопка «назад» не создаёт ещё одну
комнату. Например:

```text
https://mobile.chesson.me/game/tej1jat4
```

В `client/src/hooks/useRestoreGame.ts` ограничить автоматическое восстановление
предыдущей игры главными экранами. Сейчас хук срабатывает на смену любого пути и
может перенаправить пользователя из нового создания или приглашения в старую
комнату. Явные переходы `/create-room?autoStart=1` и `/game/{roomId}` должны иметь
приоритет. В mobile проверить аналогичное поведение восстановления.

### 5. Показать приглашение в комнате

Использовать существующие `WaitingScreen` и блок копирования ссылки. Проверить,
что до подключения соперника приглашение видно сразу. Для отправки другу удобно
использовать общий адрес `https://chesson.me/game/{roomId}`: Nginx уже направляет
его на нужную версию игры по устройству получателя. Сам создатель остаётся на
`game.chesson.me/game/{roomId}` или `mobile.chesson.me/game/{roomId}`.

На мобильном уже есть системная отправка через `navigator.share`; сохранить
копирование как альтернативу. Не переносить `autoStart` и другие параметры
создания в ссылку приглашения: друг присоединяется к существующей комнате.

### 6. Проверить весь путь и измерить результат

- Выбор 3+2, 10+0 и нестандартного времени передаётся в реальные таймеры комнаты.
- Переключатель AI передаётся без изменения значения.
- Пользователь без аккаунта и авторизованный пользователь попадают в комнату.
- Переход работает на обоих доменах и после мобильного редиректа.
- При перезагрузке, двойном действии и повторном эффекте создаётся одна комната.
- Предыдущая незавершённая игра не перехватывает новое создание и приглашение.
- При ошибке API есть повторная попытка, при открытии приглашения нет нового POST.
- Копирование и системная отправка ведут друга в ту же комнату с другого устройства.
- В Метрику передаются события нажатия CTA, создания комнаты, копирования ссылки,
  подключения соперника и первого хода; источник входа сохраняется для этой воронки.
